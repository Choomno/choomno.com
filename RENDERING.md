# Rendering the Borromean rings complement

The homepage renders the intrinsic view in the complete finite-volume hyperbolic
manifold S³ minus the Borromean rings. It uses SnapPy's `L6a4` triangulation
(eight ideal tetrahedra), not an arbitrary octahedral reflection quotient.
The canonical decomposition has two regular ideal octahedra and three torus cusps.

## Sources considered

- [SnapPy](https://github.com/3-manifolds/SnapPy): its
  [inside-view renderer](https://snappy.computop.org/manifold.html#snappy.Manifold.inside_view)
  traces hyperbolic geodesics through actual tetrahedron face pairings.
  Its [raytracing source](https://github.com/3-manifolds/SnapPy/tree/master/src/snappy/raytracing)
  supplies the manifold-data export. SnapPy is GPL-2.0-or-later.
- [non-euclidean_VR](https://github.com/henryseg/non-euclidean_VR): browser ray
  marching for Thurston geometries and quotients, by Coulon, Matsumoto, Segerman,
  Trettel and contributors. Its [official demonstrations](https://3-dimensional.space/)
  include hyperbolic manifolds. GPL-3.0-or-later; no code is bundled here.
- [hypVR](https://github.com/hawksley/hypVR): an older browser implementation
  of hyperbolic navigation. No code is bundled here.
- [Thurston, §3.4](https://library.slmath.org/books/gt3m/PDF/3.pdf):
  construction of the Borromean complement by two ideal octahedra.

## Mathematical computation

`borromean-data.json` is generated by `tools/export-borromean.py` using SnapPy
3.3.2's `ManifoldHP('L6a4')` and `IdealRaytracingData`. It records the manifold
identification, triangulation signature, high precision shape calculation,
face pairing matrices, outward face normals, cusp identities and horospheres.
The three cusp cross sections have area 2 each and are pairwise disjoint.

The exact shape parameters are either `1+i` or `(1+i)/2`. The data includes
an independently checkable Gaussian rational certificate for all eight edge
equations and six peripheral completeness equations. Their products equal 1
exactly. Edge angle sums are also checked numerically to be 2π, excluding the
other logarithmic branches. The high precision numerical shapes agree with
the exact candidates to better than 10⁻⁵⁰.

The renderer in `intrinsic.js` / `app.js` is a small independent implementation
of analytic hyperboloid ray tracing, using the mathematical data exported
from SnapPy. It does not bundle or port SnapPy's GLSL shader. For the Lorentz
form ⟨x,y⟩ = −x₀y₀+x₁y₁+x₂y₂+x₃y₃, a geodesic with unit tangent v at p is

    γ(t) = cosh(t) p + sinh(t) v.

A face with outward normal n is reached when

    tanh(t) = −⟨p,n⟩ / ⟨v,n⟩.

At a face crossing both point and tangent are transformed by the recorded
face pairing; traversal then continues in the adjacent tetrahedron. Camera
motion uses the same quotient identifications. A cusp horosphere has equation
⟨x,h⟩=−1 for a scaled future null vector h. Its intersections are obtained by
solving the resulting quadratic in tanh(t). The three colors refer consistently
to the three cusps, including across face identifications.

## What appears in the image

The colored surfaces are boundaries of disjoint cusp neighborhoods. They give
visible objects in an otherwise empty hyperbolic manifold, as one does when
illustrating the geometry of a link complement. They are not embedded round
rings in Euclidean space. Looking along a geodesic sees repeated lifts of
these surfaces; their apparent shapes arise from intrinsic perspective.
Lighting is a camera-facing artistic shading choice, not a global illumination
simulation. There is no artificial distortion applied to Euclidean geometry.

## Precision and limits

Exact gluing equations certify the underlying complete structure; the browser
is not an exact-arithmetic theorem prover. Exported matrices are rounded to
doubles, then uploaded as GPU float32 values. The shader uses analytic
geodesics and intersections rather than a numerical ODE integrator.
A bounded face-crossing count (48 / 96 / 160 with Low / Medium / High detail)
and a distance cutoff of 24 can omit distant features. Grazing intersections
can be sensitive to float32 rounding. No claim of certified pixel accuracy is made.
The default detail also limits pixel resolution to the CSS pixel size.

## Reproduce

Serve the repository root over HTTP:

    python -m http.server 8000 --bind 127.0.0.1

No build step or browser library is required for the renderer. WebGL 2 is
required; MathJax 3.2.2 is fetched from jsDelivr. Existing secondary pages keep
their shared header, footer and MathJax configuration.

To regenerate data in a Python environment with `snappy==3.3.2` installed:

    python tools/export-borromean.py

Run independent checks:

    node --experimental-default-type=module tests/intrinsic.mjs
    python tests/exact_gluing.py

The JSON contains provenance for the exported mathematical data. SnapPy's
source and license remain available at the linked upstream repository.
